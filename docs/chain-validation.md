# 本地科研 Agent 闭环验收

日期：2026-10-06。阶段提交：ca0a019。平台：Windows x64、Java 21、Python 3.13.5、Ollama qwen3:8b。验证服务使用端口18125和独立文件数据库，结束后已停止。

## 实测结果

1. 项目1保存二次优化方法笔记；生成任务1检索到 validation-method，并通过 writeArtifact 保存标准库训练脚本和说明，状态 SUCCEEDED。
2. 人工检查真实生成文件后，通过创建运行与批准接口执行 artifacts/train.py；Run1为 SUCCEEDED，退出码0，11个指标点，loss从4.0下降到0.04611686018427385。
3. 分析任务2实际调用 inspectExperiment(1) 后保存报告，状态 SUCCEEDED；报告使用实测数值并提出需人工确认的对照实验。
4. 重启后仍可查询成功任务及Run1；后续任务65再次调用 inspectExperiment并写报告，状态 SUCCEEDED。任务内消息保存于独立H2 memory ID，另有存储对象重建和隔离测试。
5. 当前版本 mvnw.cmd -B -ntp verify 成功，9项测试通过。新增测试覆盖实验观察的项目隔离、MCP initialize/list/call、跨项目拒绝、Origin拒绝和缺少协议头拒绝。

## 留存与限制

完整案例见 examples/ollama-feedback-case：实际生成脚本、指标、stdout、模型报告、工具事件和人工审阅记录。

分析任务33出现一次IllegalArgumentException，原日志未保留详细异常原因；加入可选DEBUG堆栈日志后下一次分析成功，未把该成功视为已经定位/修复任务33的根因。没有无限重试。

模型报告仍会出现不支持的命令参数和不准确的产物清单/数学解释，已逐条记录人工审阅。数值读取链路通过，不等于所有自然语言分析正确。审批继续保留，不自动执行模型提出的命令。

首次独立数据库启动命令遗漏H2 MySQL模式导致迁移失败，修正URL后新独立库启动成功。Windows运行中的jar占用导致一次重打包失败，停止验证进程后最终verify成功。没有删改用户数据库。

当前结论：本地首版“资料→生成→审批运行→实际结果观察→分析/下一步草拟”已经实跑贯通，可作为简历中经验证的最小闭环。长实验、自主修改/重跑、论文复现质量、Linux/Docker运行与实验室共享仍未验收。
